# 房型陷阱识别

## 核心约束

**陷阱识别结论必须基于实时互联网搜索获取的数据（L1）或用户提供的信息（L0）。** 不凭经验推断、不凭历史案例假设。

---

## 陷阱1：钟点房伪装过夜房

### 现象

OTA 将钟点房（Transit / Day Use）与标准过夜房混排在同一房型列表中，名称相近、床型相同、面积相同，用户可能误订。

### 实时识别方法

在采集房型列表时，逐房型检查名称关键词：

| 关键词 | 置信度 | 处理 |
|--------|--------|------|
| Transit / Day Use / Hourly / Short Stay | 高 | 标记 `[疑似钟点]⚠️`，继续查房型详情 |
| 3h / 6h / 12h / 3小时 / 6小时 / 半天 | 高 | 标记 `[疑似钟点]⚠️`，继续查房型详情 |
| 价格明显偏低（如 HKD 70 vs 正常 HKD 152） | 中 | 结合面积/床型相同 → 标记 `[疑似钟点]⚠️` |

### 识别流程

```
逐房型检查
├─ 名称含 Transit/Day Use/Hourly → [疑似钟点]⚠️，查房型详情
├─ 名称含 3h/6h/12h → [疑似钟点]⚠️，查房型详情
├─ 无明确时长标记但价格 < 正常过夜价50% → 搜索该房型的详细描述
│   ├─ 描述含"3小时""日间使用" → [钟点]⚠️
│   └─ 描述未提及时长 → [疑似钟点]⚠️
└─ 未见时长限制线索 → [时长未确认]，需查详情；未确认前可标 [疑似过夜/需复核]
```

### 案例

```
示例数据不可复用为事实；实际任务必须实时重新获取。
{OTA} {酒店名}:
  {房型A} | {价格/晚，页面明确按晚入住} → [过夜]
  {房型B Transit 3h} | {价格/3h} → [钟点]⚠️（名称含 Transit+3h）
  {房型C Transit 6h} | {价格/6h} → [钟点]⚠️（名称含 Transit+6h）
```

### 输出要求

钟点房在房型对比表中单独分组，使用 ⚠️ 标记，并附加说明：
```
⚠️ Transit 房型与 {按晚入住房型} 面积/床型相同或相近时，
   必须核对使用时长；如需过夜，需确认页面明确支持按晚入住。
```

## 陷阱2：不含税价伪装全包价

### 现象

OTA 在房型列表默认展示税前价，税费/服务费以小字标注，用户以为看到的是总价。

### 实时识别方法

在采集价格时检查：

| 检查项 | 位置 | 判定 |
|--------|------|------|
| 价格旁有"不含税""excl. tax""++" | 价格数字旁 | ❌ 不含税 |
| 价格旁有"含税""incl. tax""总价" | 价格数字旁 | ✅ 含税 |
| 价格旁无任何税费标注 | 需展开房型详情确认 | ⚠️ 默认怀疑不含税 |
| 页面底部有"价格不含XX%税费" | 页脚 | ❌ 所有价格均不含税 |

### 处理规则

- OTA 明确标注含税 → 直接使用
- OTA 标注不含税或未标注 → 标注 `⚠️ 不含税/税费未确认`
- 有多OTA同一房型价格时 → 统一比较税前价（排除税差干扰）

## 陷阱3：不可退款价作为默认展示价

### 现象

OTA 默认展示最低价（通常是不可退款价），需要展开才能看到灵活价。

### 实时识别方法

查看房型卡片/列表中的价格选项：

```
同一房型的价格展示
├─ 仅1个价格 → 查看取消政策
│   ├─ 不可退款 → 标注"最低价=不可退款价，灵活价未展示"
│   └─ 可退款 → 直接使用
└─ 2个价格并列 → 
    ├─ 低价标注"不可退款" / "Non-refundable" → 两个都记录
    └─ 高价标注"灵活取消" / "Free cancellation"
```

### 输出要求

```
| 房型 | 不可退款价 | 灵活价 | 差额 | URL/页面 | 获取时间 | 可信度 |
|------|-----------|--------|------|----------|----------|--------|
| {房型A} | {价格A} | 未展示 | — | {URL/页面} | {YYYY-MM-DD HH:mm} | L1 |
⚠️ {OTA} 当前页面只展示不可退款价，灵活价需点击房型展开确认
```

## 陷阱4：房型名称虚标

### 现象

OTA 用高级词汇命名普通房型，如 "Suite" 实际是普通 Studio、"Deluxe" 实际是无特殊设施的基础房。

### 实时识别方法

| 名称含 | 检查维度 | 真实判定 |
|--------|---------|---------|
| Suite / 套房 | 面积是否 > 40m² / 是否有独立客厅 | 否 → 虚标 |
| Deluxe / 豪华 | 设施是否比基础房型多(浴缸/景观/更大面积) | 否 → 虚标 |
| Executive / 行政 | 是否有行政酒廊/专属楼层 | 否 → 虚标 |
| Premium / 尊享 | 面积是否比标准房大 > 20% | 否 → 虚标 |

**判定依赖**：必须从 OTA 页面获取面积、设施对比、用户评价中关于房型的描述 → 三者交叉验证。

### 输出要求

虚标房型标注 `[名称虚标]` + 实际判定：
```
"Deluxe Studio" → [名称虚标] 实际与普通Studio面积/设施无差异
```

## 陷阱5：同一房型多价格混淆

### 现象

同一房型在同一OTA展示多个价格（含早/不含早、可退/不可退），但排列方式容易混淆。

### 实时识别方法

展开每个房型 → 查看价格选项列表 → 按维度分类：

| 价格变体 | 标记 |
|----------|------|
| 含早餐 vs 不含早餐 | 分别记录 |
| 可退款 vs 不可退款 | 分别记录 |
| 含税费 vs 不含税费 | 取含税费价 |
| 不同支付方式价 | 取标准支付价 |

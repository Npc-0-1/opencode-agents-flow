# Daily Memory

## 核心概念

本 skill 使用**用户自定义话题**组织记忆。没有固定分类，所有话题由用户在聊天中自然创建。

- 每个话题是一个独立目录：`memories/<话题名>/`
- 话题内按月份分文件：`YYYY-MM.md`
- 单文件超过 10MB 时序号分卷：`YYYY-MM-01.md`、`YYYY-MM-02.md`
- **`references/main-memory.md`** 是所有话题的总索引。每次使用本 skill **必须先读这个文件**。

## 触发边界

只在闲聊和日常记录中使用。

适合记录：
- 用户明确要求保存的日常信息
- 习惯、偏好、兴趣、近况
- 情绪状态、想法、长期关注点
- 人际关系背景
- 健康、作息、娱乐偏好

不要记录：
- 技术决策、项目状态、代码问题
- 模型训练、超参数
- opencode 配置
- 一次性无长期价值的闲聊
- 过度敏感隐私

技术记忆仍使用 `memory` skill。

## 使用流程

### 读取（闲聊开始时，或用户提到"之前说过/还记得"）

1. **先读** `references/main-memory.md`，获取所有话题总览和近期摘要。
2. 根据当前聊天内容，判断是否匹配已有话题：
   - **精确匹配**：直接读对应话题目录下的最新月份文件。
   - **模糊匹配**：在 main-memory.md 的话题索引中搜索关键词；如有多个候选，依次读各话题最新月份文件的前几段做判断。**不要跳过这一步**——用户在时间线上可能会用不同措辞描述同一话题。
   - **无匹配**：当前话题为新话题，准备新建目录和索引。
3. 按需分层读取：
   - 只需近期上下文时，读最新月份文件。
   - 需要追溯历史时，按时间倒序读取更早月份。
   - 能引用旧记忆时优先引用，让对话自然接续。

### 写入（用户要求保存，或判断值得长期保留）

1. 确定话题名称：优先用用户原话中的话题关键词做目录名。
2. 检查 main-memory.md 是否已有该话题：
   - **已有**：在对应 `memories/<话题>/` 目录下找到当前月份文件，追加条目。
   - **没有**：创建 `memories/<话题名>/` 目录 → 创建当月文件 → 在 main-memory.md 添加话题索引。
3. 写入条目后，更新 main-memory.md 中该话题的摘要和最近更新时间。
4. 去重、不泄露隐私、不过度记录。

### 模糊检索引导

当用户提到可能与已有话题相关但措辞不同时：

1. 在 main-memory.md 的话题索引中搜索关键词。
2. 找不到精确匹配时，读取各话题最新文件的摘要段。
3. 向用户确认方向："你之前聊过的 [话题X] 是不是和这个相关？需要我引用那部分记忆吗？"
4. 用户确认后再读完整历史；否则当作新话题创建。

## 分卷策略

- 主策略：`memories/<话题名>/YYYY-MM.md`（话题 + 月份）
- 兜底：单文件接近或超过 10MB 时，按序号分卷：`YYYY-MM-01.md`、`YYYY-MM-02.md`

## 写入原则

- 简洁记录事实，不夸大推断。
- 区分事实、用户表达和助手推断。
- 主记忆只保留摘要和索引，细节在话题文件中。
- 隐私内容只记录必要摘要，不保存敏感原文。
- 写入前去重，已有同类信息则更新旧条目而非重复开新。
